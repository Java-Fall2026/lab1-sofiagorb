## Структура

```
src/main/java/ua/common/BaseEntity.java   готовий клас, не змінюйте
src/main/java/ua/<домен>/model/           ваші сутності
src/main/java/ua/<домен>/util/            ValidationHelper, FormatHelper, <Домен>Utils
src/main/java/ua/<домен>/Main.java        демонстраційний клас
```

`<домен>` — коротка назва вашої предметної області: `hotel`, `library`, `parking` тощо.

## Як зібрати і запустити

```
./gradlew build
./gradlew run
```

У Windows замість `./gradlew` пишіть `gradlew.bat`.

Перед першим `run` впишіть свій клас у `build.gradle`:

```groovy
application {
    mainClass = 'ua.hotel.Main'
}
```

Після кожного пушу репозиторій збирається автоматично — стежте за бейджем угорі. Червоний бейдж = код не компілюється = робота не перевіряється.

## Бенчмарк пошуку (Map vs List)

Тестування проведено на колекції з 100 000 об'єктів Customer (5 ітерацій прогріву JVM + 10 вимірювань).

| Сценарій пошуку | GenericRepository (LinkedHashMap) | Лінійний пошук у ArrayList |
| :--- | :---: | :---: |
| Перший елемент | 266 090 нс | 3 290 нс |
| Останній елемент | 328 870 нс | 6 989 630 нс |
| Відсутній елемент | 145 250 нс | 6 958 940 нс |

Висновок: Пошук за ключем у Map (GenericRepository) має складність $O(1)$ і працює стабільно швидко незалежно від позиції елемента. Лінійний пошук у List має складність $O(n)$: для першого елемента він знаходить збіг одразу, але для останнього або відсутнього змушений перебирати всі 100 000 записів, тому працює у 20–45 разів повільніше.
